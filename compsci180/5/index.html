Project 4 | Neural Rendering

From camera calibration to novel-view synthesis with NeRF

This project asks a direct question: given many photos of a scene from different viewpoints, can a model learn a representation of that scene well enough to render new viewpoints that were never directly photographed? The page follows the full pipeline from camera calibration through novel-view synthesis.

Input Multi-view image sets plus calibrated camera intrinsics and poses
Methods Positional encoding, ray sampling, volume rendering
Output Rendered views, training curves, and orbit animations from unseen viewpoints

What the model must learn

  • Recover the camera geometry needed to interpret each training image.
  • Represent a 3D scene with a neural model instead of a fixed voxel grid or mesh.
  • Render colors by integrating predictions along camera rays.

Pipeline

  • Calibrate intrinsics and estimate camera poses from marker observations.
  • Validate the representation with a 2D neural field on image coordinates.
  • Train NeRF on multiview data with ray sampling and volume rendering.
  • Repeat the full pipeline on a self-captured object.
What The Model Does

A plain-language view of the rendering pipeline

Camera geometry first

Every training pixel must be tied to a known camera origin and direction. Without calibration and pose estimation, the model has no consistent 3D frame in which to learn the scene.

Query the scene along rays

For each pixel, points are sampled along a ray between near and far planes. The network predicts color and density at those sampled 3D locations.

Integrate into a final pixel

The sampled predictions are combined with differentiable volume rendering. Regions with higher predicted density contribute more strongly to the final color.

Pixel-to-ray conversion Turn image coordinates into world-space rays 
def pixel_to_ray(K, c2w, uv):
    ray_o = np.array(c2w[:3, 3])
    x_c = pixel_to_camera(K, uv, s=1.0)
    x_w = transform(c2w, x_c)
    ray_d = x_w - ray_o
    ray_d = ray_d / np.linalg.norm(ray_d, axis=-1, keepdims=True)
    ray_o = np.broadcast_to(ray_o, ray_d.shape)
    return ray_o, ray_d

def sample_along_rays(rays_o, rays_d, n_samples=32,
                      near=2.0, far=6.0, perturb=True):
    t = np.linspace(near, far, n_samples)
    pts = rays_o[:, None, :] + rays_d[:, None, :] * t[None, :, None]
    return pts
Differentiable volume rendering Convert densities and colors into a pixel color 
def volrend(sigmas, rgbs, deltas):
    deltas = torch.full_like(sigmas, float(deltas))
    alphas = 1.0 - torch.exp(-sigmas * deltas)
    Ts = torch.cumprod(
        torch.cat([torch.ones_like(alphas[:, :1]),
                   1.0 - alphas[:, :-1]], dim=1),
        dim=1
    )
    weights = alphas * Ts
    return torch.sum(weights * rgbs, dim=1)
Stage 1

Camera calibration and pose estimation for self-captured training data

OpenCV calibration and marker-based pose estimation are used to recover the camera geometry needed for NeRF. This converts raw photos into a usable training set with known camera-to-world transforms.

Stage 2

2D neural field as a controlled representation experiment

Before moving to the full 3D setting, a smaller coordinate-to-color network is trained on a single image. This isolates the effect of positional encoding and network capacity in a simpler environment.

Stage 3

Benchmark NeRF on the Lego scene

The benchmark scene is used to validate the implementation before training on self-captured data. The intermediate snapshots show how geometry and appearance emerge over optimization.

Stage 4

Training NeRF on self-captured data

The benchmark pipeline is repeated on a self-captured object after pose estimation and dataset assembly. The same rendering and evaluation logic is then used to produce training and novel-view outputs.

Key point

The project is end-to-end: data capture, calibration, ray generation, model training, and novel-view rendering all have to agree for the final result to work.
